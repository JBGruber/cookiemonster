# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this package is

`cookiemonster` is an R package for storing browser cookies in an encrypted,
local "cookie jar" and using them in HTTP requests made with `httr2`, `httr`,
`curl` or `chromote`. Cookies can be added from a Netscape `cookies.txt` file,
a cookie string, a live `rvest`/chromote session, or straight from a browser's
on-disk cookie database (`get_cookies_from_browser()`).

## Layout

| Path | Purpose |
|---|---|
| `R/set.r` | `add_cookies()` (entry point), `store_cookies()`, `default_jar()`, parsers for cookie files, cookie strings and chromote sessions |
| `R/get.r` | `get_cookies()`: read the jar, filter by domain/key, drop expired cookies, format output (`data.frame`, `string`, `vector`, `list`) |
| `R/delete.r` | `delete_cookies()` |
| `R/req_cookiemonster_set.r` | `req_cookiemonster_set()`: httr2 request helper |
| `R/encryption.r` | `encrypt_vec()` / `decrypt_vec()`: AES-CTR encryption of cookie values in the jar, key from env var `COOKIE_KEY` |
| `R/browser.r` | `get_cookies_from_browser()` and its internals (`find_cookiejar()`, `read_cookie_db()`, `prep_db()` S3 generic). Currently Firefox only. |
| `R/utils.r` | `url_get_domain()`, `is_expired()` |
| `R/sysdata.rda` | Internal data: the `cookie_dirs` table. **Generated**, do not edit by hand. |
| `data-raw/cookie_dirs.R` | Source of `cookie_dirs` (OS × browser → profile directory). Run it to regenerate `R/sysdata.rda`. |
| `tests/testthat/` | testthat (3rd edition) tests, one file per source file |
| `inst/extdata/cookies.txt` | Example Netscape cookie file used in examples/tests |
| `vignettes/cookies.Rmd` | Main vignette |
| `README.Rmd` → `README.md` | Edit the `.Rmd`, then knit |
| `man/`, `NAMESPACE` | Generated by roxygen2. Do not edit by hand. |

## The common cookie schema

Every cookie source is converted to a tibble with exactly these columns, in
this order (the Netscape cookie file layout):

| column | type | meaning |
|---|---|---|
| `domain` | chr | cookie domain (normalised with `url_get_domain()` when stored) |
| `flag` | lgl | "include subdomains", i.e. the domain had a leading dot |
| `path` | chr | cookie path |
| `secure` | lgl | only send over HTTPS |
| `expiration` | POSIXct | expiry; session cookies use `NA`, `0` or `-1` (see `is_expired()`) |
| `name` | chr | cookie name |
| `value` | chr | plain-text value (encrypted only inside the jar) |

New parsers must produce this schema so `store_cookies()` and
`get_cookies()` keep working.

## Conventions

- Base R pipe `|>`; R >= 4.1.
- Errors and messages through `cli` (`cli::cli_abort()`, `cli::cli_warn()`,
  `cli::cli_alert_*()`), not `stop()`/`warning()`.
- Packages in `Suggests` (`DBI`, `RSQLite`, `dplyr`, `jsonlite`, `curl`, ...)
  must be guarded with `rlang::check_installed()` before use and called with
  `pkg::fun()`. Only add to `Imports` when unavoidable.
- Use `.data$col` inside dplyr verbs (`@importFrom rlang .data`).
- Internal functions get `#' @noRd`.
- Exported functions need full roxygen docs with `@examples` (wrap anything
  that touches a real browser or the user's jar in `\dontrun{}`).
- British English in docs (`Language: en-GB`); the package's tone is playful
  (cookie puns are welcome in user-facing docs, not in code comments).
- Update `NEWS.md` under the development version heading for user-visible
  changes.

## Gotchas

- `get_cookies_from_browser()` calls `requireNamespace("curl")` *before*
  connecting with RSQLite on purpose (libcurl symbol clash in some RSQLite
  binaries). Keep that order.
- Browser databases are locked or in WAL mode while the browser runs; always
  work on a copy in a temp directory.
- `Sys.info()[["sysname"]]` returns `"Linux"`, `"Windows"` or `"Darwin"`
  (not `"macOS"`).
- Tests must not depend on a real browser being installed: use fixtures in
  `tests/testthat/fixtures/` and `testthat::local_mocked_bindings()`. Live
  browser tests must `skip_if()` the browser isn't found and `skip_on_cran()`.
- Never print, log or commit real cookie values.
